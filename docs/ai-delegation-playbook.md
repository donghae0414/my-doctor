# AI 위임 플레이북 — 언제, 어떻게 AI에게 일을 시킬 것인가

> 원문: [[arena-park-original]] (@arena_park, "AI에게 일을 잘 시키는 법" 3부작)
> 이 문서는 원문 20개 원칙에서 실행 가능한 판단 기준·파이프라인·프롬프트를 추출한 것.

**한 줄 요약**: AI에게 답을 달라고 하지 말고, 내 생각 공간을 넓히게 하라. 사람은 문제를 짚고 고르고 결정하며, AI는 그 공간을 뒤지고 채우고 계산한다.

---

## 1. 언제 쓰나 — 위임 판단

### 1-1. 첫 질문: "지금 내가 모르는 것이 무엇인가?"

```
내가 모르는 것이...
├─ 결과다   → 연역 (예: 판매량 100% 오르면 매출은?)
│             → AI에 전부 위임. 계산 공장으로 쓴다. (신뢰도 ~90점)
├─ 규칙이다 → 귀납 (예: 지난 20년간 이런 상황은 어떻게 됐나?)
│             → AI에 전부 위임. 사람은 비교 기준만 정한다. (신뢰도 ~90점)
└─ 원인/프레임이다 → 귀추 (예: 왜 잘 팔리는데 주가는 빠졌지?)
              → 사람 주도. AI는 "후보 생성기"로만 쓴다. (신뢰도 ~30점)
```

- 연역·귀납은 고민하지 말고 무조건 AI. 사람이 직접 하면 낭비다.
- 귀추가 승부처다. AI는 기발한 가설을 만들 수 있지만, 그것이 새로운 설명인지 훈련 데이터의 재조합인지 스스로 판별하지 못한다. 그래서 결정권은 사람이 갖는다.

### 1-2. AI에게 넘기면 안 되는 5가지 (최종 결정은 항상 사람)

1. **무엇이 놀라운가** — 비정상치 탐지는 AI가 해도, "세계관을 깨는 이상함"의 의미는 사람이 안다
2. **무엇이 중요한가** — 숫자로 큰 것 ≠ 전략적으로 중요한 것
3. **어떤 가설이 탐색할 가치가 있는가** — 가능한 가설 ≠ 유의미한 가설
4. **무엇을 믿을 것인가** — AI는 반대되는 주장도 모두 논리적으로 쓴다
5. **무엇을 세상에 내보낼 것인가** — 평판/윤리/맥락/취향의 결정

### 1-3. 반대로, 사람이 더 이상 직접 하면 안 되는 것

자료 정리 · 회의록 초안 · 표/비교표 만들기 · 초안 문장 · 헤드라인 뽑기 · 숫자/형식 변환 · 번역 → 전부 AI에게.

> 가장 생산적인 사람은 AI를 가장 많이 쓰는 사람이 아니라, **넘길 일을 가장 정확히 구분하는 사람**이다.

## 2. 어떻게 쓰나 — 인사이트 생산 파이프라인

| # | 단계 | 담당 | 하는 일 |
|---|------|------|---------|
| 1 | 문제공간 정의 | 사람 | "분석해줘"가 아니라 구체적 모순을 짚어준다 ("못 만들어서 못 파는데 주가는 왜 -13%?") |
| 2 | 이상한 후보 대량 생산 | AI | 결론 금지. 동시에 사실이기 어려운 것 20개 (예상/관측/차이 형식) |
| 3 | 진짜 이상한 것 선별 | 사람 | 두 문장 사이의 "사라진 연결"을 알아보는 건 사람만 가능 |
| 4 | 가설 확산 | AI | 가설 15개+, 영역 강제 분산 (회계/재무/경쟁/규제/공급망...) |
| 5 | 가설 선별 (3개) | 사람 | 3기준: ① 놀랍나? ② 새로운 생각인가? ③ 반증 가능한가? |
| 6 | 케이블 끊기 (전제 검증) | AI | 핵심 전제 5개 추출 → 각 전제가 거짓이어도 결과가 성립하는지 반복 |
| 7 | 귀납 검증 | AI | 유사 사례 30개 수집, 동일 기준 정규화, 맞는/안 맞는 사례 분류 |
| 8 | 연역 계산 | AI | 시나리오 역산, 민감도 계산, 다른 방식으로 검산 |
| 9 | 믿을 것 결정 | 사람 | 최종 판단. "어떤 결과라면 마음을 바꿀지"까지 미리 정해둔다 |
| 10 | 산출물 변환 | AI | 검증 끝난 인사이트 1개 → 메모/차트/체크리스트/영문판 등 N개로 재사용 |

핵심 구조: **사람의 시간은 리서치가 아니라 선택에 들어간다.** (월요일 이상한 점 10개 → 가설 100개 → AI가 반례 제거 → 사람은 5개만 보고 1~2개에 시간 투자)

## 3. 바로 쓰는 프롬프트 템플릿

### T1. 이상한 후보 생성 (파이프라인 2단계)
> 결론을 내리지 마라. 이 자료들 안에서 서로 동시에 사실이기 어려워 보이거나, 일반적인 기대와 다른 방향인 사실만 20개 찾아라.
> 각 항목을 [예상했던 것 / 실제 관측된 것 / 둘 사이의 차이]로 적어라.
> 원인은 아직 설명하지 마라.

*이유: AI가 바로 설명까지 하게 두면 가장 흔한 설명으로 수렴한다.*

### T2. 가설 확산 (파이프라인 4단계)
> 아래 이상현상을 설명할 가설을 15개 만들어라.
> 단, 앞의 가설과 같은 방식이나 메커니즘의 변형은 새로운 가설로 세지 마라.
> 최소한 다음 영역을 하나씩 포함하라: 회계 / 재무 / 고객행동 / 경쟁 / 물리적 제약 / 시간차 / 규제 / 조직 인센티브 / 공급망 / 시장심리.
> 서로 동시에 참일 필요도 없다. 지금은 가능성을 넓히는 작업이다.

### T3. 케이블 끊기 (파이프라인 6단계)
> 현재 설명에서 가장 중요한 전제 5개를 찾아라.
> 전제 1이 거짓이라고 가정한다. 그래도 현재 결과가 나올 수 있는가? (전제 2~5 반복)

*변형 질문: 경쟁사가 없었다면? 가격이 절반이라면? 고객 한 곳을 제거하면? CAPEX가 1년 늦어진다면? 주가를 모른다고 가정하면 같은 결론인가?*

### T4. 귀납 검증 — 기준을 사람이 세운다 (파이프라인 7단계)
> ❌ "AI 버블과 닷컴버블을 비교해줘"
> ✅ "수요 증가율 / 공급 증가율 / 고객 집중 / 자산수명 / 공급자금융 / 가격 방향을 동일한 정의로 양쪽에서 계산해라"

### T5. 연역 계산 (파이프라인 8단계)
> PER 15/20/25/30배 각각에서 현재 시총을 설명하려면 순이익이 얼마 필요한지 계산해라.
> 현재 마진 유지 시 필요한 매출을 역산해라. 보수/기준/공격 시나리오를 만들어라.
> 각 가정이 10% 틀릴 경우 결과 민감도를 계산해라.
> 계산식을 출력하고 다른 방식으로 한번 더 검산해라.

### T6. 레드팀 (교차 검증)
> 결과물을 **다른 대화창/다른 AI**에 붙여넣고: "너는 red team이다. 이 분석이 틀리는 이유만 찾아라. 결론에 동의하지 마라."

## 4. 운영 원칙

### 역할 분리 — 최소 4역할, 편집자는 반드시 마지막
1. **연구원(Researcher)** — 가능한 한 많은 근거를 찾는다
2. **비평가(Skeptic)** — 결론을 모른 상태로 틀리는 이유만 찾는다
3. **감사(Calculator/Source Audit)** — 숫자와 근거만 검증한다
4. **편집자(Reporter)** — 모든 검증이 끝난 뒤에만 산출물을 만든다

- 글을 먼저 예쁘게 만들면 인간도 그 이야기에 설득된다. AI의 위험한 능력 = **틀린 생각을 아름답게 만드는 능력** (능력 밖 문제를 도우면 정답률이 평균 19% 하락, 그런데 틀린 답은 더 설득력 있게 보임)
- 순서는 항상 **사실 조사 → 스토리**. 반대는 금지.

### 교차 검증
- AI는 반드시 2개 이상. 불가능하면 같은 AI라도 대화방을 역할별로 분리하고 서로 맥락을 차단한다.
- 맥락은 내가 가진다. AI가 가질 필요가 없는 맥락은 주지 않는다.

### 생산성 KPI
- ❌ 보고서량/시간 (같은 일을 빨리하기)
- ✅ **검증된 새로운 인사이트/주간** (다룰 수 있는 생각의 수 늘리기)
- 시간 배분 목표: 실행 관리 10~20%, 선택/질문/판단/귀추 80%

### 인사이트 재사용
- Insight 생성은 비싸고(사람 개입 필요), Artifact 변환은 싸다(AI).
- 검증된 인사이트 1개 → 임원 메모/체크리스트/차트/회의 질문/비교표/영문판/모니터링 지표로 즉시 변환.

### 사람의 새 역할 = "AI가 탐색할 공간을 만드는 사람"
질문을 잘하는 것보다 한 단계 더: ① 무엇을 이상하게 볼지 ② 어떤 세계를 상상할지 ③ 무슨 전제를 빼볼지 ④ 무엇을 비교할지 ⑤ 어떤 결과라면 마음을 바꿀지 — 이 다섯을 정하는 것이 사람의 일이다.

## 5. 안티패턴 체크리스트

- [ ] "인사이트 찾아줘" / "분석해줘"라고 통째로 던지지 않았나? → 문제공간을 짚어줬는가 (T1)
- [ ] AI가 후보 생성 단계에서 바로 설명/결론까지 하게 두지 않았나? → 흔한 설명으로 수렴한다
- [ ] 가설을 확산 없이 받지 않았나? → 영역 강제 분산 (T2)
- [ ] 같은 AI(같은 대화창)에게 "내 분석 맞아?"라고 검증시키지 않았나? → 자기 내러티브 합리화
- [ ] 편집(예쁜 글)을 검증보다 먼저 하지 않았나? → 사실 조사 → 스토리 순서
- [ ] 귀추(원인/프레임/중요도) 결정을 AI에게 넘기지 않았나? → 후보만 받고 결정은 사람
- [ ] 연역/귀납(계산/조사/비교/초안)을 사람이 직접 하고 있지 않나? → 낭비. AI에게
- [ ] 인사이트 1개를 결과물 1개로 끝내지 않았나? → N개 Artifact로 재사용
